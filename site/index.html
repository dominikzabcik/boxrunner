Self-hosted GitHub Actions runners

CI on the box you already pay for.

Every job gets a fresh container that is gone when the job ends. Your GitHub App key never touches the box. And your test suite keeps every core while the rest runs on what it leaves idle.

Priority classes

Your tests keep every core. The rest waits its turn.

Light jobs run in an idle-priority class, scheduled by Linux's SCHED_IDLE: they use any core your main job is not using, and give it back the instant it wants it. Flip the switch to see the same box without it.

Key custody

The key stays in your Worker. The box gets tokens that expire.

The GitHub App can administer your repositories, so its private key lives only in a Cloudflare Worker you deploy. The box can ask for one thing: a runner for one job.

● the vault holds your key   ● tokens travel to your box   ● one job's container forms and dissolves

If someone owns your boxthey get runner registrations for your private repositories for minutes, not the key that can delete them.

When not to use it

        
Honest limits.

      

      

        
Public repositoriesAnyone who can open a pull request could run code on your box. The Worker refuses them.

        
macOS or Windows jobsboxrunner runs Linux containers, on amd64 and arm64.

        
A fleet of machinesOne Worker serves one box today. GARM and Actions Runner Controller manage fleets.

        
Untrusted codeJobs share the host's kernel, like every container.

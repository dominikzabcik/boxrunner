CI on the box you already pay for.

Self-hosted GitHub Actions runners on one Linux box. Every job gets a fresh container that is gone when the job ends, and your GitHub App key never touches the box.

Your tests keep every core. The rest waits its turn.

boxrunner runs two classes of runner on the same box. The normal class gets the box’s full speed. The idle class runs only on cores nothing else wants, so your test suite never waits for it.

Normal class, runs-on: boxrunner
Keeps the whole box. Put the test suite and the build here.
Idle class, runs-on: boxrunner-light
Runs only on cores the normal class leaves idle, through Linux’s SCHED_IDLE, and gives a core back the moment the main job wants it. CodeQL, link checks and deploys go here.

The key stays in your Worker.

The GitHub App can administer your repositories, so its private key lives in a Cloudflare Worker you deploy, on the free plan. GitHub hands the key straight to the Worker during setup, so nobody copies it, and the box never holds it.

AThe Worker
Holds the GitHub App key and asks GitHub for runners on the box’s behalf.
BThe token
The box holds a token that can only ask for runners. Nothing else.
CYour box
If someone takes it over, they get runner registrations for minutes, not the key.

    Deploy it to Cloudflare with one click, on the free plan. It asks for a setup secret: keep it, because the setup page needs it.

  2. Create the GitHub App

    Open /setup on your Worker, enter the secret and confirm on GitHub. Install the App on the private repositories that should use your box.

  3. Install the agent

    The setup page shows the line above with your Worker and token filled in. The installer checks the binary’s checksum and build attestation before anything runs.

  4. Use it

    In a workflow, change runs-on: ubuntu-latest to runs-on: boxrunner. That is the whole migration.

Also in the box

Docker inside jobs
Opt-in, through Sysbox: each job gets its own Docker daemon with no privileged mode, and a job’s root is not root on the host.
A doctor
boxrunner doctor checks that a job cannot reach the host, your private network or the cloud metadata service.
Fork warnings
The doctor and the dashboard warn when a private repository runs workflows from fork pull requests without approval, or hands them secrets or write tokens.
Checked images
The job image is built only from an actions/runner image whose build attestation CI has verified.
A fallback
Opt-in: while the box is silent, a variable in your workflow sends jobs to GitHub’s runners instead.
Alerts
A webhook for ntfy, Discord or Slack says when the box goes silent, and when a repository’s jobs wait with no runner starting, with the likely cause.
Unserved jobs
The dashboard lists jobs nobody here runs: a label that is not a class, a repository the Worker does not serve, a paused class.
A dashboard
Served by the Worker: the box, its runners and their jobs.
Prometheus metrics
Opt-in: runners, jobs, durations, queue time and disk, on a port jobs cannot reach.

Four cases where it is the wrong tool.

i.

Public repositories

The Worker refuses them. Anyone who can open a pull request could run code on your box.

ii.

macOS or Windows jobs

boxrunner runs Linux containers, on amd64 and arm64.

iii.

A fleet of machines

One Worker serves one box, or several if you split classes or repositories. Actions Runner Controller and GARM manage fleets.

iv.

Untrusted code

Jobs share the host’s kernel, like every container does.

Questions

Something else? Ask on GitHub Discussions.

Do I change anything else in my workflows?
No. You change runs-on and nothing else. Send light jobs such as CodeQL or a link check to boxrunner-light so they run on idle cores.
Can jobs run Docker?
Yes, when you add --docker to the install command. Docker then works inside jobs through Sysbox, with no privileged mode, and a job’s root is not root on the host.
What happens when the box is down?
With fallback turned on, jobs run on GitHub’s runners while the box is silent. Without it, they wait for the box. An alert webhook, if you set one, tells you either way.
How fast do jobs start?
6 to 12 seconds after they are queued, and 2 seconds when a warm runner is waiting.
What does it cost?
Nothing. boxrunner is Apache-2.0, the Worker fits Cloudflare’s free plan and GitHub does not bill self-hosted minutes. You pay for the box, which you already do.
Does it work with public repositories?
No. The Worker refuses them, because anyone who can open a pull request could run code on your box.
How do I watch it?
The Worker serves a dashboard and sends alerts, and boxrunner can export Prometheus metrics. On the box, boxrunner status lists runners and recent jobs.
How do I patch the box?
boxrunner drain lets running jobs finish and takes no new ones. Patch and reboot, run boxrunner upgrade when a release is out, then boxrunner resume.
